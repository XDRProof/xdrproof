# SET_TRUST_LINE_FLAGS fails with SET_TRUST_LINE_FLAGS_INVALID_STATE (/docs/corpus/entries/failure-set-trust-line-flags-invalid-state)

Where it sits, inside `LedgerCloseMeta` (CAP-0035):

- H-C1: OperationResult.set_trust_line_flags.invalid_state in a closed ledger
- H-C10: AUTHORIZED and AUTHORIZED_TO_MAINTAIN_LIABILITIES both set

## The shape

A transaction whose SET_TRUST_LINE_FLAGS operation fails at apply is still written into the closed ledger: its fee is charged, its sequence number is consumed, and nothing it did is kept. The result carries the operation's code (invalid_state). Setting AUTHORIZED_TO_MAINTAIN_LIABILITIES on an AUTHORIZED trustline without clearing AUTHORIZED would leave both set.
