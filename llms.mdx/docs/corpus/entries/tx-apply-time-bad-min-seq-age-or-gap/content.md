# A transaction with minSeqLedgerGap fails at apply after a bump-to-0 in the same ledger (/docs/corpus/entries/tx-apply-time-bad-min-seq-age-or-gap)

Where it sits, inside `LedgerCloseMeta` (CAP-0021, CAP-0046):

- H-C16: TransactionResult.txBAD_MIN_SEQ_AGE_OR_GAP in a closed ledger: seqLedger moved earlier in the ledger

## The shape

Core applies a ledger's classic phase before its Soroban phase and re-checks the source account, sequence number, signatures and sequence-age preconditions at apply (TransactionFrame::commonValid; OperationFrame::checkSignature with forApply). Here a classic transaction earlier in the same ledger runs BUMP_SEQUENCE with bumpTo 0 on the source: the sequence number does not change, but seqLedger moves to this ledger (BumpSequenceOpFrame.cpp maybeUpdateAccountOnLedgerSeqUpdate), so this transaction's minSeqLedgerGap of 1 is no longer met and it fails with txBAD_MIN_SEQ_AGE_OR_GAP.
