# A transaction valid at submission fails txBAD_SEQ at apply (/docs/corpus/entries/tx-apply-time-bad-seq)

Where it sits, inside `LedgerCloseMeta` (CAP-0046):

- H-C16: TransactionResult.txBAD_SEQ in a closed ledger: source sequence bumped earlier in the ledger

## The shape

Core applies a ledger's classic phase before its Soroban phase and re-checks the source account, sequence number, signatures and sequence-age preconditions at apply (TransactionFrame::commonValid; OperationFrame::checkSignature with forApply). Here a classic transaction earlier in the same ledger bumps the source account's sequence number, so this Soroban transaction fails with txBAD_SEQ. Its fee is charged and its sequence number is not consumed (tx_changes_before is empty). Readers that assume txBAD_SEQ never reaches a ledger, or that every failed transaction consumed a sequence number, get this wrong.
