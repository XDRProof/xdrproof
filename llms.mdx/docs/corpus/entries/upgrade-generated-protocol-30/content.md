# A fresh network's upgrade ledger: protocol 0 to 30 and base reserve 0.5 XLM (/docs/corpus/entries/upgrade-generated-protocol-30)

Where it sits, inside `LedgerCloseMeta` (pre-cap, CAP-0046):

- H-F1: LEDGER_UPGRADE_VERSION 0 -> 30 and LEDGER_UPGRADE_BASE_RESERVE in one ledger; initial ConfigSettingEntry rows created
- H-F6: upgradesProcessing changes in a different order in every core run

## The shape

The first upgrade of a fresh standalone network sets the protocol to 30 and the base reserve in one ledger; crossing the Soroban protocol creates every Soroban config setting at its initial value, all in upgradesProcessing. Its change order differs in every core run (20 of 20), its content never.
