# A fee bump whose inner transaction fails at apply with txNO_ACCOUNT (/docs/corpus/entries/tx-apply-time-inner-no-account)

Where it sits, inside `LedgerCloseMeta` (CAP-0015, CAP-0046):

- H-C16: InnerTransactionResult.txNO_ACCOUNT at apply: the inner source was merged earlier in the ledger; the fee source remains
- H-C2: txFEE_BUMP_INNER_FAILED with inner txNO_ACCOUNT

## The shape

The inner transaction was valid when queued; a classic transaction earlier in the same ledger changed its source, and core re-checks the source at apply (TransactionFrame::commonValid, processSignatures): the inner source was merged earlier in the ledger; the fee source remains. The outer result is txFEE_BUMP_INNER_FAILED with txNO_ACCOUNT inside; the fee source pays. Readers that expect inner results to carry only operation failures, or treat a queued transaction as valid, get it wrong.
