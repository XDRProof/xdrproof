# Apply order is not transaction-set order, and differs by network and protocol (/docs/corpus/entries/ledger-apply-order-differs-from-set-order)

Where it sits, inside `LedgerCloseMeta` (CAP-0063):

- H-C12: tx_processing order differs from tx_set order; classic phase before Soroban phase

## The shape

The transaction set lists transactions in phases sorted by hash; core applies the classic phase first, then the Soroban phase, each in an order shuffled by the hash of the whole set (TxSetFrame.cpp ApplyTxSorter). The same recipe gives a different apply order on each network and protocol. Readers that number transactions by their position in the set, or assume one order, misattribute results.
