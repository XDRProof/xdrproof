# SAC trustline with no event (/docs/corpus/entries/sac-trust-creates-trustline)

Where it sits, inside `LedgerCloseMeta` (CAP-0073):

- H-D1: InvokeHostFunctionOp → LedgerEntryChange.created.TrustLineEntry (no operation event)

## The shape

Since CAP-0073 a contract call (the Stellar Asset Contract's `trust` function) can create a classic trustline. The trustline appears only as a created ledger entry in the operation's changes: there is no CHANGE_TRUST operation and no operation event. Readers that learn about trustlines from operation types or events drop it. wallet-backend recorded the balance but no TRUSTLINE/ADD state change (#731).

## Variants

The variants are **generated** by a standalone stellar-core v30.0.0 at protocols 30 and 28. On most of them the order of the operation's changes is not stable between core processes, so those pin an order-normalised hash and list every raw ordering seen.

| The operation emits no event: an indexer that waits for an event or a CHANGE_TRUST operation never learns about this trustline. | length `0` | snapshot |

The trustline is found by matching a change "in any order": an indexer must never depend on the order of changes within an operation.

## What it reproduces

[wallet-backend#731](https://github.com/stellar/wallet-backend/issues/731), [stellar-etl#460](https://github.com/stellar/stellar-etl/issues/460)

`make replay` feeds this entry's **P28** variant to two wallet-backend builds through a mock stellar-rpc. Build `764a4f5b` **drops the trustline**: no TRUSTLINE/ADD state change is recorded. Build `c152783c`, "record SAC-created trustline state changes" (#734, the fix for #731), records it. See [Replay](/docs/tools/replay).
