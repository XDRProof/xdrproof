# EXTEND_FOOTPRINT_TTL fails with RESOURCE_LIMIT_EXCEEDED after a config upgrade (/docs/corpus/entries/failure-extend-footprint-ttl-resource-limit-exceeded)

Where it sits, inside `LedgerCloseMeta` (CAP-0046):

- H-C6: EXTEND_FOOTPRINT_TTL resource_limit_exceeded at apply
- H-C1: OperationResult.extend_footprint_ttl.resource_limit_exceeded in a closed ledger
- H-F10: a config upgrade that leaves existing code above the maximum contract size

## The shape

A transaction whose EXTEND_FOOTPRINT_TTL operation fails at apply is still written into the closed ledger: its fee is charged, its sequence number is consumed, and nothing it did is kept. The result carries the operation's code (resource_limit_exceeded). From protocol 23 an extension fails only when the entry is larger than the network allows. A config upgrade lowered the maximum contract size to its floor of 2000 bytes; kit2's 5364-byte Wasm is now too large to extend. The maximum goes back two ledgers later.
