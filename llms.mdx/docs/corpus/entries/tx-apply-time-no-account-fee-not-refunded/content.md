# A Soroban transaction fails txNO_ACCOUNT at apply and its fee is never refunded (/docs/corpus/entries/tx-apply-time-no-account-fee-not-refunded)

Where it sits, inside `LedgerCloseMeta` (CAP-0046):

- H-C16: TransactionResult.txNO_ACCOUNT in a closed ledger: source merged earlier in the ledger
- H-C13: Soroban fee source merged before the refund: fee_charged is the full maximum, no refund change or event

## The shape

Core applies a ledger's classic phase before its Soroban phase and re-checks the source account, sequence number, signatures and sequence-age preconditions at apply (TransactionFrame::commonValid; OperationFrame::checkSignature with forApply). Here a classic transaction earlier in the same ledger merges the source account after its fee was charged, so this Soroban transaction fails with txNO_ACCOUNT. The refund has nowhere to go: there is no post-apply fee change and no refund event, and fee_charged is the full declared maximum (TransactionFrame.cpp:998-1001). Readers that compute the fee as charge minus refund, or expect a refund for every Soroban transaction, get it wrong.
