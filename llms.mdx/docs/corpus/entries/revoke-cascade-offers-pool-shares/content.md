# Deauthorizing a trustline removes offers, redeems pool shares into claimable balances and deletes the pool (/docs/corpus/entries/revoke-cascade-offers-pool-shares)

Where it sits, inside `LedgerCloseMeta` (CAP-0035, CAP-0038):

- H-D9: revocation creates claimable balances from pool shares and removes offers
- H-C10: trustline fully deauthorized (flags 4: only the clawback bit)
- H-C8: pool entry removed by a revocation
- H-F6: a ledger whose change order differed in every one of 20 core runs; minority orderings ship as files

## The shape

SET_TRUST_LINE_FLAGS clears every authorization on mm's XPF trustline. Core removes mm's three XPF offers, redeems mm's pool shares into two claimable balances for mm (no CREATE_CLAIMABLE_BALANCE), removes the pool-share trustline and, mm being the last shareholder, the pool itself. Readers that only create balances and pools from their own operations miss all of it.
