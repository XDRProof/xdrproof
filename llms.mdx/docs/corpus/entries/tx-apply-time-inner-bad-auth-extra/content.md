# A fee bump whose inner transaction fails at apply with txBAD_AUTH_EXTRA (/docs/corpus/entries/tx-apply-time-inner-bad-auth-extra)

Where it sits, inside `LedgerCloseMeta` (CAP-0015, CAP-0046):

- H-C16: InnerTransactionResult.txBAD_AUTH_EXTRA at apply: the inner transaction carries two signatures both needed at submission; at apply the master key alone meets the raised weight, so the second goes unused (SignatureChecker stops at the needed weight)
- H-C2: txFEE_BUMP_INNER_FAILED with inner txBAD_AUTH_EXTRA

## The shape

The inner transaction was valid when queued; a classic transaction earlier in the same ledger changed its source, and core re-checks the source at apply (TransactionFrame::commonValid, processSignatures): the inner transaction carries two signatures both needed at submission; at apply the master key alone meets the raised weight, so the second goes unused (SignatureChecker stops at the needed weight). The outer result is txFEE_BUMP_INNER_FAILED with txBAD_AUTH_EXTRA inside; the fee source pays. Readers that expect inner results to carry only operation failures, or treat a queued transaction as valid, get it wrong.
