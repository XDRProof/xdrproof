# A forged address signature: the host fails ed25519 verification with an SCError of type crypto (/docs/corpus/entries/auth-forged-signature-crypto-error)

Where it sits, inside `LedgerCloseMeta` (CAP-0046):

- H-A7: an auth entry naming alice whose signature fails verification; alice authorized nothing
- H-C6: SCError.SCE_CRYPTO (invalid_input) in diagnostic events

## The shape

bob submits a call carrying an auth entry for alice whose signature covers another nonce. The host verifies it with ed25519 and fails with Error(Crypto, InvalidInput), then escalates to an auth error and the call traps. alice authorized nothing, yet her address sits in the transaction. Readers that index auth-entry addresses as participants, or decode SCError as host error types only, both go wrong.
