# A fee bump whose inner transaction fails at apply with txBAD_AUTH (/docs/corpus/entries/tx-apply-time-inner-bad-auth)

Where it sits, inside `LedgerCloseMeta` (CAP-0015, CAP-0046):

- H-C16: InnerTransactionResult.txBAD_AUTH at apply: the only key that signed the inner transaction was removed earlier in the ledger
- H-C2: txFEE_BUMP_INNER_FAILED with inner txBAD_AUTH

## The shape

The inner transaction was valid when queued; a classic transaction earlier in the same ledger changed its source, and core re-checks the source at apply (TransactionFrame::commonValid, processSignatures): the only key that signed the inner transaction was removed earlier in the ledger. The outer result is txFEE_BUMP_INNER_FAILED with txBAD_AUTH inside; the fee source pays. Readers that expect inner results to carry only operation failures, or treat a queued transaction as valid, get it wrong.
