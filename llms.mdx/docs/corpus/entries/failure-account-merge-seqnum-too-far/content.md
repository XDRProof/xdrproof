# ACCOUNT_MERGE fails with ACCOUNT_MERGE_SEQNUM_TOO_FAR (/docs/corpus/entries/failure-account-merge-seqnum-too-far)

Where it sits, inside `LedgerCloseMeta` (pre-cap):

- H-C1: OperationResult.account_merge.seqnum_too_far in a closed ledger
- H-C11: merge after a bump past the ledger's starting sequence

## The shape

A transaction whose ACCOUNT_MERGE operation fails at apply is still written into the closed ledger: its fee is charged, its sequence number is consumed, and nothing it did is kept. The result carries the operation's code (seqnum_too_far). Operation 0 bumps the sequence number past this ledger's starting sequence (ledger << 32); merging could let the account be recreated with a lower number, so core refuses (MergeOpFrame.cpp, isSeqnumTooFar). Operation 0 reports success in the failed transaction.
